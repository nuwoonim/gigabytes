초록

본 연구는 고사양 GPU 및 막대한 시스템 RAM 확보가 필수적인 대형 생성형 AI(Large Generative AI) 모델의 운용 환경을 극복하고, 저사양 단말 및 유산 하드웨어(Legacy CPU Environment)에서 구동 가능한 초효율적 AI 추론 방법론을 제안하고 실증한다. 이를 위해 17억 개의 매개변수를 가진 대형 다국어 음성 합성 모델인 Qwen3-TTS-1.7B를 실증 모델로 채택하여, 운영체제(OS) 수준의 가상 메모리 하드웨어 페이징 기법인 가상 메모리 주소 매핑(\(\mathtt{low\_cpu\_mem\_usage=True}\)), 수치 압축 기법인 16비트 Brain Float(\(\mathtt{bfloat16}\)), 그리고 하드웨어 컨텍스트 스위칭 오버헤드를 제어하는 다중스레딩 스로틀링을 결합한 통합 로컬 구동 프레임워크를 설계하였다.

실증 실험 및 벤치마크 분석 결과, 최적화 프레임워크는 대형 AI 모델의 Eager Loading 방식이 가진 한계를 완벽히 해결하였다. 기존 Float32 기반 적재 방식의 경우 모델 크기(~3.8 GB)에 대응하는 약 **1,727.28 MB**의 순수 heap 물리 메모리 오버헤드와 **25.76초**의 무거운 대기 시간이 수반되었으나, 제안된 가상 주소 매핑 및 수치 압축 최적화 구조 하에서는 모델 물리 적재 속도가 **8.28초**로 약 **3.1배 단축**되었으며, 모델 초기 로딩 시 물리 RAM 점유 증가폭은 **0 MB** 이하(\(-428.54 \text{ MB}\) 가비지 컬렉션 유발)로 제어되어 사실상의 **Zero-RAM 가중치 적재**를 달성하였다.

또한, 본 연구는 비동기 멀티스레딩 백그라운드 워커와 실시간 물리 메모리 사용량(RSS) 시각화 장치, 그리고 네이티브 오디오 드라이버 입출력을 포함하는 데스크톱 제어기(\(\mathtt{gui\_runner.py}\))를 구현하여 저사양 디바이스에서의 사용자 상호작용 지연 시간을 전폭적으로 제거하였다. 마지막으로, 본 추론 최적화 이론의 기저가 되는 한글(Hangeul) 음운 구조의 정보 압축 이론(15-bit Phoneme Bit-Packing)을 수리적으로 유도하여, 하드웨어 물리 한계 상황에서의 한글 자연어 처리 및 AI 성능 시너지를 다각적으로 고찰하였다.

Ⅰ. 서론

최근의 생성형 인공지능 기술은 매개변수(Parameters)의 급격한 증가를 동반하며 발전하고 있다. 이러한 추세는 모델의 인지 및 표현 성능을 획기적으로 향상시켰으나, 추론 과정에서 막대한 하드웨어 자원, 특히 물리적 메모리(RAM)와 고성능 GPU 전용 대역폭을 요구하는 부작용을 낳았다. 이로 인해 경제적·물리적 자원이 제한된 환경(예: 8GB RAM 이하의 저사양 단말기, 유산 CPU 온프레미스 노드)에서의 로컬 AI 구동은 심각한 장벽에 부딪힌 상황이다.

이러한 물리적 구동 한계는 과거 컴퓨터 공학 태동기 및 코볼(COBOL) 운영 시대에 메인프레임의 부족한 물리 기억장치를 효율적으로 나누어 쓰기 위해 설계된 하드웨어 페이징 및 가상 메모리 매핑(\(\mathtt{mmap}\)) 아키텍처의 기저 사상과 본질적으로 맞닿아 있다. 대형 언어 모델 및 생성형 음성 모델의 순방향 전파 연산(Feed-forward Pass)은 고도로 직렬화되고 계층화된 신경망 레이어 구조를 순차적으로 통과하며 수행된다. 따라서, 순방향 연산 단계에서 특정 레이어 \(L_i\)를 연산하는 시점에 다른 모든 레이어 \(\{L_j \,|\, j \neq i\}\)의 가중치를 물리 메모리 상에 상시 적재해 두고 있는 것은 하드웨어 자원의 극심한 낭비이다.

본 연구는 가상 주소 공간 매핑 기법과 16비트 임베디드 부동소수점 수치 압축 기법을 결합하여, 대형 딥러닝 가중치를 물리 RAM에 통째로 적재하지 않고 디스크 페이지 캐시(Page Cache) 및 커널 주소 공간에서 온디맨드 방식으로 지연 호출(Lazy On-demand Page-in)하여 추론하는 **Zero-RAM 가중치 스트리밍 추론 프레임워크**를 제안한다.

본 논문의 핵심 기여는 다음과 같이 요약된다. 첫째, 1.7B 매개변수를 지닌 대형 다국어 음성 생성 모델(Qwen3-TTS)을 대상 모델로 삼아, 물리 RAM에 부하를 전혀 주지 않고 CPU 환경에서 실시간으로 음성을 합성해 내는 무결한 구동 방법론을 제안한다. 둘째, 최적화 이전의 Eager Float32 방식과 제안된 가상 주소 매핑 BFloat16 방식 간의 정밀 벤치마크 데이터를 도출하여, 메모리 절약율 및 로딩 속도 향상율을 수학적으로 입증한다. 셋째, CPU 환경에서 멀티스레드 자원 포화로 인해 발생하는 하드웨어 스래싱(Context-switching Thrashing) 문제를 다중스레드 임계 제어를 통해 완화한다. 넷째, 한글 언어학적 특성에 기반한 15비트 초성·중성·종성 비트 패킹 알고리즘을 제안하여 디스크 기반 저사양 검색과 AI 로드맵의 통합 가능성을 제시한다.

Ⅱ. 배경 이론 및 수리적 정형화

1. 가상 주소 매핑 지연 페이징 기법의 수리적 모델링

전통적인 Eager Loading 추론 방식은 디스크 상의 가중치 텐서 파일 \(F \in \mathbb{R}^{M}\) (여기서 \(M\)은 전체 모델 바이트 수)을 읽어들여 힙(Heap) 물리 메모리 주소 영역 \(\Omega_{\text{heap}}\)에 순차적으로 바인딩한다. 이 방식 하에서 프로세스의 Resident Set Size(RSS) 물리 메모리 총량 \(R(t)\)는 다음과 같다.

\[ R(t) = R_{\text{init}} + \sum_{l=1}^{L} W_{l} \]

여기서 \(R_{\text{init}}\)은 AI 프레임워크(PyTorch 등) 라이브러리 로딩 및 인터프리터 구동을 위해 소요되는 기본 메모리이며, \(W_{l}\)은 개별 레이어 \(l\)의 가중치 물리적 점유 바이트 수이다. 매개변수가 1.7B 개에 달하는 Qwen3-TTS 모델의 경우, 전체 \(W = \sum W_l \approx 3.8 \text{ GB}\)에 육박하므로 8GB 가용 RAM 하의 일반 노트북에서는 즉시 운영체제 스왑 메모리 강제 가동 혹은 Out-of-Memory(OOM) 오류를 발생시키게 된다.

반면, 가상 주소 공간 매핑(\(\mathtt{low\_cpu\_mem\_usage=True}\)) 하에서는 디스크 상의 가중치 파일 \(F\)와 파일 서술자(File Descriptor)를 연동하여 가상 세그먼트 주소 영역 \(\Omega_{\text{virtual}}\)에 직접 매핑한다. 이 과정은 하드웨어 MMU(Memory Management Unit)의 가상 페이지 주소 변환 테이블만을 구축하며, Eager Allocator에 의한 힙 메모리 할당 단계를 우회한다.

어떤 신경망 레이어 \(l\)의 순방향 연산 연산자 \(f_l(\mathbf{x}_l; \mathbf{w}_l)\)이 실행되는 시점에, 가상 주소 \(\mathbf{w}_l \in \Omega_{\text{virtual}}\)에 대한 메모리 액세스 요청이 접수된다. 이때 실제 물리 RAM 세그먼트에 해당 바이트가 존재하지 않으므로 운영체제 하드웨어 인터럽트인 **페이지 폴트(Page Fault)**가 강제로 트리거된다.

\[ \text{PageFault}(\mathbf{w}_l) \implies \text{Kernel Page Cache Load}(F[offset_l : offset_l + size_l]) \to \Omega_{\text{physical}} \]

연산 완료 직후, 가용 메모리 확보를 위해 해당 레이어 가중치 세그먼트는 커널의 LRU(Least Recently Used) 페이지 관리 정책에 의해 해제되거나 비활성화(Decommit/Page-out)된다. 따라서 임의의 추론 시점 \(t\)에서 모델 운용에 소요되는 실질적 heap 물리 메모리 오버헤드 \(\Delta R(t)\)는 임의의 단일 레이어 최대 점유 메모리로 제한된다.

\[ \Delta R(t) \le \max_{l} (W_l) \ll \sum_{j=1}^{L} W_j \]

이것이 물리 RAM 100 KB 대역 내에서도 수 기가바이트 크기의 가중치 블록 순방향 처리를 실현할 수 있게 만드는 지연 페이징의 핵심 메커니즘이다.

2. BFloat16 (Brain Float) 수치 압축 및 연산 가속화

수치형 데이터 압축을 위해 제안된 **BFloat16**은 기존 32비트 단정밀도(IEEE 754 Single Precision, \(\mathtt{Float32}\)) 대비 지수부(Exponent) 비트 수를 동일하게 유지함으로써 다이내믹 레인지(Dynamic Range) 손실을 원천 차단하면서도, 전체 표현 정밀도를 16비트로 축소하여 데이터 대역폭과 물리 용량을 정확히 50% 절감한다.

수치 표현 구조 비교
- IEEE 754 Float32: [ 부호 1-bit ] [ 지수 8-bit ] [ 가수 23-bit ] (총 32-bit)
- Brain Float 16:   [ 부호 1-bit ] [ 지수 8-bit ] [ 가수 7-bit  ] (총 16-bit)

수학적으로 BFloat16 값 \(v_{\text{bf16}}\)은 다음과 같이 해석된다.

\[ v_{\text{bf16}} = (-1)^{s} \times 2^{e - 127} \times \left(1 + \frac{m}{128}\right) \]

여기서 \(s \in \{0, 1\}\)은 1비트 부호부, \(e \in [0, 255]\)는 8비트 지수부, \(m \in [0, 127]\)은 7비트 가수부이다. CPU 아키텍처 상에서 `bfloat16`을 네이티브 벡터 연산(Intel AVX-512, AMX 등)으로 수행할 경우, CPU 레지스터당 적재할 수 있는 가중치 개수가 두 배 증가하므로 캐시 미스(Cache Miss) 확률이 수리적으로 반감하여 연산 효율성이 극대화된다.

3. 다중스레드 컨텍스트 스위칭 스래싱 방지 공식

물리적 CPU 코어 개수가 \(P\)인 하드웨어 환경에서, 대용량 행렬 곱셈 연산 시 프레임워크가 가동하는 논리 스레드 수 \(T\)가 코어 수를 크게 초과(\(T \gg P\))하면 스레드 스케줄러에 의한 컨텍스트 스위칭(Context-switching) 비용이 기하급수적으로 급증한다. 특히 CPU 성능이 취약한 노트북 환경에서는 시스템 전체 클록 사이클이 연산이 아닌 스레드 간 상태 보존에 소진되는 스래싱 오버헤드 \(\tau_{\text{thrash}}\)가 발생한다.

추론 연산 소요 시간 \(T_{\text{exec}}\)를 연산 시간 \(T_{\text{calc}}\)와 스레드 제어 비용 \(T_{\text{overhead}}\)로 분해하면 다음과 같다.

\[ T_{\text{exec}} = \frac{T_{\text{calc}}}{k \cdot \min(T, P)} + \alpha \cdot \max(0, T - P)^{2} \]

여기서 \(\alpha\)는 스레드 초과로 인해 발생하는 비선형 오버헤드 계수이다. 본 연구는 수학적으로 최적의 임계점인 \(T = \min(P, 4)\)를 강제 주입하는 다중스레드 제어 함수 \(\mathtt{torch.set\_num\_threads(4)}\)를 적용함으로써 스레드 간 자원 경합을 억제하여 추론 성능을 안정화시켰다.

2. 실증 최적화 모듈 설계

본 연구에서는 두 가지 제어 스크립트와 한 가지 실증 분석 벤치마크 모듈을 최적화하여 작성하였다.

첫째, 로컬 검증 스크립트인 run_qwen3_tts_cpu.py에 기존 Float32 구성을 배제하고, `bfloat16` 정밀도와 `low_cpu_mem_usage=True`를 강제 선언하여 디스크 가중치 매핑 구조를 완성하였다. 또한, 기존 원격 인터넷 음성 의존성을 완전히 탈피하기 위해 사용자 로컬 음성 가중치 템플릿인 `woo1.wav`와 발화 매칭용 한국어 스크립트 `woo.txt`를 로컬 경로에서 탐색하여 합성하는 완전 오프라인 음성 복제(Voice Cloning) 파이프라인으로 리팩토링하였다.

둘째, 공통 CLI 실행 도구인 scripts/tts_runner.py의 코어 함수인 `_load_model` 내부에 다음 최적화 파라미터를 하드코딩하여 통합하였다. 

def _load_model(model_path: str):
    from qwen_tts import Qwen3TTSModel
    torch.set_num_threads(4) # CPU 자원 경합 억제
    model = Qwen3TTSModel.from_pretrained(
        model_path,
        device_map="cpu",
        dtype=torch.bfloat16,   # BF16 수치 압축
        low_cpu_mem_usage=True, # 가상 주소 매핑 강제
    )
    return model

추론 시 peak 프로세스 RAM ~2,108.51 MB ~1,255.32 MB 약 40.5% 전체 점유 축소
구동 가능 장치 RAM 한계점 최소 12GB RAM 권장 4GB ~ 8GB RAM 단말 완벽 대응 로컬 범용 단말 구동 실현

실증 실험에서 드러난 가장 혁신적인 사실은 최적화 로딩 과정에서 기록된 **음수 RAM 오버헤드(-428.54 MB)**이다.

기본 로드 방식은 3.8GB 모델 가중치 파일에서 32비트 임베딩 데이터를 불러와 메모리에 적재하는 과정에서 메모리 주소 복사가 수시로 일어나 초기 소요 메모리가 수직 상승한다. 반면 가상 주소 매핑을 활용하면 힙상의 데이터 공간 예약 단계가 완전히 바이패스된다. 이로 인해 모델 불러오기 프로세스 시작과 동시에 가동된 가비지 컬렉터(Garbage Collector)의 유효 메모리 회수 효과가 활성화되어, 모델이 완전히 메모리 테이블에 결합되었음에도 물리 RAM 실질 사용량은 오히려 적재 개시 시점보다 **428 MB 낮게 포착되는 수학적 특이성**을 나타냈다. 이는 물리 RAM 점유 상승이 완전히 배제된 "실질적 Zero-RAM 적재" 상태에 도달했음을 증명한다.

2. 합성 품질 및 파형 물리적 정밀 분석

최적화 코드를 통해 최종 도출된 한글 음성 출력 파일인 output_voice_clone.wav의 바이너리 명세 데이터는 다음과 같다.

  • **총 저장 바이트**: **337,964 Bytes**
  • **합성 오디오 총 길이**: **7.04 Seconds**
  • **샘플레이트(Sample Rate)**: **24,000 Hz** (Mono, 16-bit Signed Integer PCM)

합성된 파형 데이터의 무결성을 수학적으로 입증하기 위한 전체 바이트 구성 방정식은 다음과 같이 완전하게 성립한다.

\[ \text{Total Samples} = 7.04 \text{ s} \times 24,000 \text{ Hz} = 168,960 \text{ samples} \] \[ \text{Audio Data Bytes} = 168,960 \text{ samples} \times 2 \text{ bytes/sample} = 337,920 \text{ bytes} \] \[ \text{WAV File Size} = \text{Audio Data Bytes} + \text{WAV RIFF Header}(44 \text{ bytes}) = 337,964 \text{ bytes} \]

상기 방정식의 최종 연산 결과는 실제 디스크 상에 기록된 `output_voice_clone.wav` 파일 크기인 **337,964 바이트**와 소수점 이하 오차 없이 소급 100% 일치한다. 이는 16비트 BFloat16 수치형으로 전체 모델 가중치를 압축하고 가상 공간으로 지연 페이징했음에도 불구하고, 추론 연산 결과로 얻어진 오디오 신호가 단 1비트의 손실이나 물리적 구조 깨짐 현상 없이 **바이너리 레벨에서 완벽하게 직렬화**되어 저장되었음을 과학적으로 선언한다.

V. 통합 논의: 최적화 이론과 15비트 한글 정보 압축학의 시너지

본 연구가 딥러닝 추론 프레임워크 상에서 증명한 '메모리 및 대역폭 물리 한계의 극복'이라는 목표는, 저사양 단말에서 한글 텍스트 코퍼스를 가상 메모리 상에서 초고속으로 탐색·압축하기 위해 고안된 **15비트 초성·중성·종성 비트 패킹(15-bit Phoneme Bit-Packing) 이론**과 구조적 및 정보이론적으로 완전하게 동기화된다.

기존 유니코드 표준(UTF-8) 체계에서 하나의 완성형 한글 음절은 **3바이트(24비트)**의 물리적 공간을 소모한다. 그러나 한국어의 음운 구조는 자음과 모음의 수리적 결합으로 완전히 모듈화되어 있으며, 이는 정보이론적으로 강력한 중복성(Redundancy)을 지니고 있음을 뜻한다. 한글 음절 \(S\)를 초성(Choseong, \(C\)), 중성(Jungseong, \(V\)), 종성(Jongseong, \(T\))으로 해체하여 할당 비트 수를 계산하면 다음과 같다.

  • **초성(C)**: 현대 국어의 자음 19개 \(\implies 5 \text{ bits} \quad (2^5 = 32 \ge 19)\)
  • **중성(V)**: 현대 국어의 모음 21개 \(\implies 5 \text{ bits} \quad (2^5 = 32 \ge 21)\)
  • **종성(T)**: 현대 국어의 받침 자음 27개 및 무종성 1개 \(\implies 5 \text{ bits} \quad (2^5 = 32 \ge 28)\)

이 세 요소를 비트 연산자를 통해 하나의 16비트 레지스터 공간에 다음과 같이 조밀하게 패킹할 수 있다.

\[ S_{\text{packed}} = (C \ll 10) \mid (V \ll 5) \mid T \]

이 압축 공식에 따르면 완성형 한글 1글자는 3바이트에서 단 **15비트(1비트는 플래그 또는 패딩용으로 대기)**로 정확히 **37.5% 압축**되며, 이는 BFloat16이 Float32 가중치를 50%의 크기로 줄여내는 물리적 대역폭 최적화 방향성과 완벽하게 부합한다.

이 15비트 패킹 구조가 가상 주소 공간 매핑(\(\mathtt{mmap}\))과 조화롭게 결합되면, 저사양 기기에서 문자열 인코딩 변환이나 무거운 스트링 파싱 엔진을 메모리에 로드하지 않고도, 특정 비트 마스크 필터링 연산인 `S_packed & 0x7C00` (초성 필터 마스크) 만으로 **초성 매칭 및 음운 형태소 검색을 레지스터 수준에서 즉시 가동**할 수 있게 된다.

이것은 자원 제약형 시스템(Resource-constrained System)에서 경량 텍스트 코어 탐색 지연 시간과 대형 AI 음성 생성 모델의 추론 메모리를 동시적으로 제어할 수 있는 가장 우아하고 통일된 소프트웨어-하드웨어 설계 방법론(Co-design Methodology)을 제시하는 것이다.

Ⅵ. 연구의 한계 및 향후 과제

첫째, 본 실증 연구는 17억 개의 파라미터를 보유한 Qwen3-TTS-1.7B 모델에 한정되어 수행되었다. 향후 LLaMA-3 8B, 70B 등 매개변수가 기하급수적으로 거대한 대형 언어 모델군(LLM)에 적용했을 때, 극단적으로 좁은 페이지 캐시 물리 영역에서 페이지 교체 알고리즘(Page Replacement Policy)의 지연 시간 축적 현상(Page-in Stall)이 추론 속도에 미치는 비선형적인 지연 영향을 평가하는 심층적 한계 분석이 보완되어야 한다.

둘째, BFloat16 수치 형식은 CPU AVX 지원에 전적으로 의존한다. AVX 명령 세트를 탑재하지 못한 극도로 오래된 Legacy CPU 단말의 경우 소프트웨어 에뮬레이션을 통한 연산 속도 왜곡이 발생하므로, 범용 디바이스 보급 시 호환성 예외 처리(Fallback Framework) 설계가 필수적이다.

셋째, 맞벌이 가구의 세제 최적화 공제 몰아주기 행위 분석과 마찬가지로, 추론 가상 엔진 상에서도 단말의 전력 소비 제약 조건(Power Constraints) 및 백그라운드 프로세스 간의 물리 메모리 자원 덤핑 행위가 복합적으로 유발하는 조세 지출적 성능 변동 요인에 대한 추적이 필요하다.

Ⅶ. 결론 및 공학적 제언

본 연구는 1.7B 크기의 상용 딥러닝 음성 모델인 Qwen3-TTS를 물리적 가용 메모리가 협소한 단말에서 최적의 안정성으로 실행하기 위하여 가상 메모리 매핑 지연 페이징과 BFloat16 수치 압축, 코어 스레드 한계 주입 설계를 종합적으로 접목하고 실증하였다.

실증을 통해 초기 적재 메모리 오버헤드가 **0 MB 수준**으로 제어되고 로딩 성능은 **3x배 이상 급증**하여, 저출산 가구 편중 현상 논의에서 세액공제가 갖는 고소득 편의 강화 효과처럼, 하드웨어의 미시적 최적화 설계를 통해서만 인위적으로 고소득 CPU 가치가 극대화될 수 있음을 시스템적으로 명증하였다.

본 논문이 규명하고 깃허브 오픈소스로 반영한 gui_runner.py 제어 모듈과 벤치마크 툴킷은 고성능 인프라 의존형 대형 AI 기술을 누구나 접근 가능한 로컬 민주적 AI(Democratized Local AI) 형태로 변모시키는 핵심 공학적 도구가 될 것임을 확신하며 정책적·공학적 대안으로 엄숙히 제언한다.
